# Decisions: public-ready

One line each: what, why, [ASSUMED] if unverified.

- Work happens on `chore/public-ready` as the prompt names it, not on the session's default branch; the prompt is explicit permission for that branch.
- Removals live only in `scripts/public-snapshot/paths-remove.txt`, applied to the cleaned copy. `main` is never edited to delete anything.
- Default mailmap is generated by `run.sh` from the history (most frequent author -> `GM-Hrishi`, everyone else -> `OneVision team member`), so `mailmap.txt` holds only overrides and no personal email is added to the repository. Deviation from "mailmap.txt default maps ..."; same outcome.
- Mailmap entries match by old email only (git form `Name <new> <old>`): annotated tags used a different display name with the same college email, and a name+email pair did not catch them.
- Tagger identities are included when building the mailmap (found in the first dry run: 5 tag objects kept the college email).
- `git-filter-repo --blob-callback` cannot key on a path (blobs have no filename), and no file that code or CI reads needed removal, so no stubs were made. Checked: the blind-results guard test only compares file names in a diff; nothing reads `docs/eval/`.
- `packages/blindgen` (generator and evaluator source) stays public: the Makefile, CI and `pyproject.toml` use it. Only the result files and the progress note that quotes the headline are removed.
- One blind-set commit message is scrubbed with `--replace-message` (results sentence and the clean-application count), not dropped, so hashes stay deterministic.
- Personal-data scan patterns exclude lockfiles, PDFs and images (registry hashes and stream bytes match the PAN and phone patterns); everything else is scanned in every revision.
- `README.md` "Planned" rows are copied from the prompt's list; no row was added. The screenshot `docs/screens/ui-polish/queue-colour.png` is used because it is synthetic and has no AICTE branding; it is from an earlier build, so the caption says so.
- Memory budget in the README is stated as "under 8 GiB, checked by `make mem-check`" because `docs/DEV-SETUP.md` still says 5.6 GB (stale after the OCR image raised the api limit); that doc is left as it is. [ASSUMED: nobody relies on the 5.6 GB figure]
- `gitleaks` for the dry run is the v8.30.1 release binary (same version as CI), downloaded from the project's GitHub release.
- `THIRD_PARTY_NOTICES.md` is generated from the pnpm and pip-licenses output of the installed environment, not from the lockfile text; licence names are the packages' own metadata, not reviewed by a lawyer. [VERIFY]
- `docs/DEMO-*` files and `CLAUDE.md` are kept by default and flagged; optional removal lines are commented in `paths-remove.txt`.
